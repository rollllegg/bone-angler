# 剧情演出与特效方案

> 目标：旁白里的动作描写不再只靠文字，改由可复用的演出层执行。  
> 状态：P1 屏幕特效、P2 道具层和 P3 特殊立绘已实现；P4 音效等素材到位后再接。

## 1. 现状

- 剧情正文在 `narrative/prose/*.md`，动作大多写成旁白，例如“取下里拉琴，弹了起来”“连忙把尾巴塞进腰带里”“画面晃了一下”。
- 剧情面板 `game/scripts/demo/story_panel.gd` 只渲染说话人、正文、选项和真名输入。
- 店铺层 `game/scripts/demo/pixel_shop.gd` 只画一张通用来客立绘（正面/转身/背面），没有特殊 NPC 立绘、道具、表情或屏幕特效。
- 现有素材是 405×243 的像素场景和 48×64 的通用来客；`cast_01/02/03` 是整张背景，不是可拆角色。
- 目前没有音效素材，`game/assets/audio/` 为空。

所以“旁白动作”既没有画面，也没有时序；玩家只能读字。

## 2. 目标与非目标

### 目标

1. 关键动作由演出层补上可见反馈；括号里的动作描写从文本框移到 cue，台词保留。
2. 演出数据化：换剧情、换特效不改运行时代码。
3. 作者只审“这里该有什么演出”，不维护时间表或动画代码。
4. 演出可跳过、可测试、可在无美术时用占位素材先跑通。
5. 复用同一套演出层，不只为孙悟空和俄耳普斯写死。

### 非目标

- 不把正文改成特效标记语言。正文仍是人写的台词和旁白。
- 不在分支图里写动画代码。
- 不做不可跳过的长过场。
- 第一版不追求完整角色动画；先解决“动作完全没有画面”的问题。

## 3. 总体结构

```text
narrative/
  prose/<case>.md                 人写：台词、必要旁白
  derived/<case>.graph.json       分支、条件、状态
  derived/cues/<case>.cues.json   AI 派生：按文本 key 挂演出，作者审
        │
        ▼ story_build
game/data/story/
  cases/<case>.json               合并 cues 后的案例数据
  text/zh.json                    正文
        │
        ▼
StoryRuntime ── step + cues ──► StoryDirector ──► StoryStage
   │                              │                 ├─ 店铺像素层（震动/缩放/换立绘）
   │                              │                 ├─ 屏幕层（闪色/淡入淡出）
   │                              │                 └─ 道具层（里拉琴/金箍棒/尾巴/灰手）
   ▼                              ▼
StoryPanel                     等待/跳过信号
```

职责：

- `StoryRuntime`：只负责“当前是哪一步、这一步有哪些 cue”。不播放动画。
- `StoryDirector`：读 cue，按顺序/并行调度，发 `started`、`finished`、`skipped`。
- `StoryStage`：真正执行震动、闪色、淡入淡出、缩放、换立绘、道具显隐。
- `StoryPanel`：文字和选项；有 `wait` cue 时暂停推进，播完再允许空格。
- `pixel_shop.gd`：保留现有通用来客逻辑，增加一个“剧情立绘/道具覆盖层”。

## 4. cue 数据

### 4.1 文件位置

```text
narrative/derived/cues/
  wukong.cues.json
  orpheus.cues.json
```

按**文本 key**挂载，key 与 `text/zh.json` 一致。这样正文、分支和演出可以分开改：

```json
{
  "orpheus.inspect.lyre.2": [
    {"type": "shake", "strength": 4, "duration": 0.35},
    {"type": "flash", "color": "#9b8fb5", "alpha": 0.2, "duration": 0.2},
    {"type": "sprite", "id": "orpheus_turn"},
    {"type": "sprite", "id": "orpheus_front", "delay": 1.0}
  ]
}
```

### 4.2 通用字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | string | `shake` / `flash` / `fade` / `zoom` / `sprite` / `prop` / `wait` / `sound` |
| `if` | string | 可选，和分支图同一套条件表达式；不命中就跳过 |
| `delay` | float | 可选，延迟多少秒开始，默认 0 |
| `duration` | float | 可选，持续时间，默认按类型 |
| `wait` | bool | 可选，是否阻塞文字推进；默认 false |
| `target` | string | 可选，`shop` / `screen` / `stage`，默认按类型 |

### 4.3 类型

| 类型 | 主要参数 | 作用 |
| --- | --- | --- |
| `shake` | `strength` 像素、`duration` | 店铺像素层震动；文字不跟着抖 |
| `flash` | `color`、`duration` | 屏幕层闪色；用于变身、琴声、打击 |
| `fade` | `color`、`to` 0/1、`duration` | 淡出/淡入；用于离场、转场 |
| `zoom` | `scale`、`center`、`duration` | 店铺镜头推拉；用于看清道具/表情 |
| `sprite` | `id`、`pose`、`flip`、`fade` | 换剧情立绘或姿态 |
| `prop` | `id`、`action` show/hide/move、`position`、`scale` | 显示/隐藏/移动道具 |
| `wait` | `duration` | 纯等待，用于控制节奏 |
| `sound` | `id`、`volume` | 音效；当前没有素材，先保留接口 |

### 4.4 执行语义

- 同一 step 的 cue 按数组顺序执行。
- `wait: true` 的 cue 会阻塞文字推进；`wait: false` 的 cue 与下一步并行。
- 一个 step 的 cue 全部结束，或所有非阻塞 cue 启动后，`StoryDirector` 发 `finished`。
- 玩家按空格/回车可以跳过当前 cue 组；跳过时直接落到最终状态（例如闪色结束、立绘已换）。
- 选项只在 cue 结束后出现；`wait` cue 未结束时不能选项。
- 条件 cue 用 `if`，例如 `{"type":"sprite","id":"monkey","if":"named"}`。

## 5. 演出层设计

### 5.1 StoryDirector

```gdscript
signal started(step_key: String)
signal finished(step_key: String)
signal skipped(step_key: String)

func play(step_key: String, cues: Array, context: Dictionary) -> void
func tick(delta: float) -> void
func skip() -> void
func is_playing() -> bool
func blocks_advance() -> bool
```

- 由 `StoryPanel.render()` 在当前 step 变化时调用；`context` 是运行时 flag，用来算 cue 的 `if`。
- 自己计时，`tick(delta)` 由面板每帧驱动；不用 Tween，测试可以直接推进时间。
- 遇到 `wait:true` 或 `type:"wait"` 时阻塞文字推进；普通 cue 启动后不再等它播完。
- 跳过时把每个 cue 直接落到终态，发 `skipped` 和 `finished`，玩家再按一次才推进正文。
- 没有 cue 的 step 立即 `finished`，不改变现有节奏。

### 5.2 StoryStage

`StoryStage` 是演出执行的唯一出口，方便测试时换成假实现：

```gdscript
func bind(shop: Node2D, screen: Control) -> void
func begin_cue(cue: Dictionary, duration: float) -> void
func finish_cue(cue: Dictionary) -> void
func reset() -> void
```

实现分层：

- **屏幕层**：`_story_screen` 是 `_stage` 下、所有 UI 之前的全屏 `Control`，里面放闪色/淡入淡出的 `ColorRect`。颜色在文字面板下方，文字始终可读。
- **店铺层**：`pixel_shop.gd` 的 Node2D 变换负责 `shake`/`zoom`；震动时整体放大约 4%，避免视口边缘露黑。
- **道具层**：`story_prop_layer.gd` 保存 405×243 世界坐标和前后层归属；`pixel_shop._draw` 先画身后道具，再画客人，最后画身前道具。
- **立绘层**：`pixel_shop.gd` 的 `story_sprite` 覆盖通用来客；`sprite` cue 切换 `wukong_disguise`、`wukong_disguise_turn`、`wukong_monkey`、`wukong_turn`、`orpheus_front`、`orpheus_revealed`、`orpheus_turn` 等 48×64 立绘，并带 1 像素深色描边。
- **声音层**：P4 未实现；`sound` cue 已有数据契约，但 `SOUND_IDS` 为空。

### 5.3 与面板的时序

```text
runtime 进入 step
  → panel 显示说话人/正文，并 director.play(step_key, cues)
  → cue 播放中：空格只跳过本组 cue，不推进正文
  → cue 结束：下一次空格推进
```

文字和演出同时开始，避免出现“文字说画面晃了，但画面没动”。带 `wait` 的 cue 只锁住推进，不遮挡文字；玩家可以按空格把本组 cue 直接落到终态。括号里的动作描写不进入文本框，改由 cue 表达。

## 8. 作者工作流

1. 作者照常写 `narrative/prose/<case>.md`。
2. AI 读正文，生成 `narrative/derived/cues/<case>.cues.json`；不确定的动作标 `[待确认]`。
3. 作者只审 cue 表：
   - “这里应该晃屏还是闪一下？”
   - “这个动作要不要停顿？”
   - “这句话是否还需要保留？”
4. 构建校验；模拟器统计 cue 覆盖；UI 测试实际播放。
5. 作者不改 JSON 也能提意见；AI 改 cue，不动正文。

- cue 文件的 key 必须存在于对应案例的 `text/zh.json`。

## 11. 验收标准

- 关键动作旁白有 cue；纯对话和次要动作可以只留文字，不强行加特效。
- 玩家在演出播放中按空格可以跳过，不会卡在不可推进状态。
- 立绘热点和决定按钮在演出结束后正常出现；已调查热点保留并画灰。
- 构建期能发现：cue key 不存在、cue 类型未知、素材 id 未声明、条件 flag 未声明。
- 无 cue 的案例仍按现有方式运行。
- 演出只作用于像素场景/屏幕层，文字面板保持可读，不被震动或闪色干扰。
- 接受/拒绝后接待窗口只结案送客；结局后果在当天队列结束后的“今日余波”报告显示，不在窗口里提前播。俄耳普斯殉情延迟到第 3 天琴手回访，阿努比斯称心直接进整局结局。

当前验收：20 组 headless 测试 1851 项 0 失败；`story_build` 3 案例、117 文本 key、0 错误；`story_sim` 阿努比斯 18 条 / 俄耳普斯 120 条 / 悟空 260 条路径。截图见 `game/build/validation/story-hotspots-wukong.png`、`story-hotspots-orpheus.png`、`story-hotspots-investigated.png`、`story-hotspots-wukong-revealed.png`、`story-hotspots-orpheus-revealed.png`、`story-orpheus-lyre.png`、`story-anubis-judgment.png`、`story-anubis-ending.png`、`day-report.png`。

## 12. 风险与取舍

| 风险 | 处理 |
| --- | --- |
| 特殊立绘/道具美术量大 | P1 先做屏幕特效；P2 先用占位图跑通，再换正式 PNG；P3 接静态换图 |
| 生图模型风格不统一 | 固定 prompt 模板、固定色板、固定尺寸；生成后用 PerfectPixel 统一像素网格 |
| 透明背景/边缘杂色 | 生成时要求纯色背景；用脚本抠色/清理边缘；必要时用图像编辑接口修 |
| 震动/闪色让文字难读 | 只震店铺像素层；闪色放在文字层下方；提供强度上限 |
| 演出阻塞操作 | 所有 cue 可跳过；`wait` 上限 3 秒；跳过落到终态 |
| cue 与正文错位 | cue 以文本 key 为锚；构建期校验 key 存在 |
| 作者不想维护 cue 表 | AI 生成，作者只审；cue 文件不进正文 |
| 结局文字在接待窗口里像“未卜先知” | 接待只结案送客，`aftermath` 延后到当天收工的余波报告 |

### 14.3 结论

**能做。** 本轮把第一批 8 个道具全部抽样，并生成/编辑了 5 个角色状态；文生图能出可用的像素道具和角色，图像编辑能改光线、加轮廓光，也能把俄耳普斯转成背面，而且角色基本保持一致。

但不是一个接口就能直接出游戏素材，必须加一段后处理：

1. **透明背景**：接口返回的是白底，不是真透明；需要从四角泛洪抠白，不能用“把白色全删掉”，否则会伤到角色高光。
2. **水印**：每张图右下角都有“图片由AI生成”，编辑接口也会重新加；需要裁掉或覆盖。**水印处理要先确认平台条款是否允许去除/裁切；如果条款不允许，就不能直接用于游戏素材，需要换授权模型或保留水印。**
3. **目标尺寸**：PerfectPixel 输出的是原生像素网格（本次从 30×28 到 216×211 不等），还要按 32×32/48×64 做裁剪和缩放。
4. **风格一致性**：同一套 prompt 模板下，悟空偏细、俄耳普斯偏粗；需要用固定模板、固定色板和“48×64/32×32 像素网格”约束，必要时用编辑接口统一光线。
5. **暗色角色**：俄耳普斯原图在深色店铺背景上会糊成一团；编辑接口加浅色边缘光后可用，建议把“边缘光”写进角色 prompt 模板。
6. **构图**：悟空的金箍棒会伸出 48×64；建议悟空用 64×64，或把金箍棒拆成独立 `staff` 道具。

### 14.4 正式流程（已落地）

- `game/tools/prepare_generated_asset.py`：水印区域填白、调 PerfectPixel、抠背景、连通域去杂点、按目标框缩放；配置在 `game/tools/story_assets.json`。
- 生成原图放 `game/art/source/story/`，最终图放 `game/assets/art/story/`。
- `game/assets/SOURCES.md` 记录模型、prompt、生成日期、编辑步骤和后处理参数；每张正式图旁边的 `.json` 记录哈希、像素网格和处理参数。
- 角色统一 48×64；悟空如果保留完整金箍棒用 64×64；道具 32×32 或 48×48。
- 俄耳普斯统一走“原图 + 边缘光编辑”两步；转身用编辑接口生成背面，保持同一套斗篷。
- P1+P2+P3 已使用正式 PNG；后续新素材沿用同一套配置和脚本，不需要再写临时后处理。

### 15.3 交互

- 带 `wait` 的 cue 播放时，空格只跳过本组 cue，不推进正文；再按一次才到下一句。
- 非阻塞 cue 与正文并行；玩家推进后，新 step 会把上一组未结束的 cue 落到终态。
- 第 1 天最后一位是普通立绘的阿努比斯伪装，不换特殊立绘，也没有 cue。
- 悟空到达显示伪装，叫破/结局切本相；伪装离场用 `wukong_disguise_turn`，本相离场用 `wukong_turn`。
- 俄耳普斯查看里拉琴时切背影，延迟切回正面；叫破后切回 `orpheus_revealed`，离场用 `orpheus_turn`。
- 屏幕闪色/淡入淡出位于所有 UI 之下；震动/缩放只作用于 405×243 店铺像素层。
- 切换来客时重置演出/热点状态，并清掉上一位客人的离场动画，避免两个立绘叠在柜台。
- 道具分前后层：金箍棒、尾巴、云在客人身后，里拉琴/硬币/药碗/灰手/桃子在身前；金箍棒藏在背后，只露出肩头和腰下的两端。
- 每个立绘带一张暗色影子图，填掉手臂/腿之间的透明小缝，避免浅色地板从缝里透出来像白边。
- 调查过的选项用 `locked_if` / `locked_text` 保留在立绘热点上并画灰，不消失。
- 调查选项不再渲染成列表：`choice.hotspot.rects` 是 48×64 立绘坐标，由 `story_hotspot_layer.gd` 映射到舞台；悬停显示动作名，点击走同一个 `choose(id)`。
- 选择接受/拒绝后，接待窗口立即结案并只保留“结束招待”送客；不再在窗口里播“后来……”的长结局。
- 结局文字存进 outcome 的 `aftermath`，在当天收工后的“今日余波”报告里显示；如果后面还有下一天，报告关闭后才进入下一天。俄耳普斯殉情是例外：第 3 天琴手回访后才在报告里出现。
- 阿努比斯的最终听证是线性对话，Shift 继续；到 `judgment` 节点自动打开天平面板，输入 0 到当前渡魂币总数，提交后播放恢复平衡动画，再进入 0/全部/其他分支。面板放在来客脸部上方，不遮挡立绘；天平素材是 `scale.png`，面板按输入值倾斜后回到平衡。
- 称心结束不弹当天报告，直接进入结局卡：隐藏顶部 HUD、左侧药剂/属性面板、右侧队列/收费面板，只保留店铺场景、阿努比斯立绘、天平、居中的结局文字和“空格 / 点击 返回标题”。结局文字逐字显现，第一次输入补全文字，第二次返回标题。
