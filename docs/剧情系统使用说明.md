# 剧情系统使用说明

> 系统设计见 `docs/剧情系统设计.md`。这篇只讲怎么加案例、怎么编译、怎么跑测试、怎么实际试玩。
>
> 动作旁白的演出与特效见 `docs/剧情演出与特效方案.md`（P1 屏幕特效、P2 道具、P3 特殊立绘已实现，P4 音效待素材）。

## 1. 目录

```text
narrative/
  seeds/                 人写：故事种子
    wukong.md
    orpheus.md
  derived/               AI 生成：分支图、调度、世界状态、结局
    wukong.graph.json
    orpheus.graph.json
    schedule.json
    world.json
    endings.json
    story_build_report.md
    simulation_report.md
    combinations.csv
  prose/                 人写：按节点分节的正文
    wukong.md
    orpheus.md
    endings.md

game/scripts/story/                   运行时：表达式、状态、文本、案例、单案例推进
game/scripts/demo/story_panel.gd      接待窗口里的剧情面板
game/tools/story_build.gd             编译与校验
game/tools/story_sim.gd               路径枚举与报告
game/tools/Run-StoryLab.ps1           剧情测试场启动脚本
game/data/story/                      编译产物，游戏只读这里
```

`game/data/story/` 是生成目录，不手改；改 `narrative/` 后重新编译。

## 2. 写一个案例

1. **种子**：`narrative/seeds/<id>.md`。写清谁、想要什么、藏了什么、玩家能做什么、必须发生、绝不能发生。
2. **分支图**：`narrative/derived/<id>.graph.json`。结构见第 3 节。
3. **正文**：`narrative/prose/<id>.md`。按节点分节，台词用 `说话人：内容`，旁白直接写。不用写 key。
4. **排期**：在 `narrative/derived/schedule.json` 的 `slots` 里加 `{day, slot, case}`；`slot` 从 0 开始。
5. **世界状态**：需要跨案例的 flag 写进 `narrative/derived/world.json`。
6. **整局结局**：需要新结局写进 `narrative/derived/endings.json`，正文写在 `narrative/prose/endings.md`。
7. 跑编译和测试。

## 3. 分支图约定

```json
{
  "id": "case_id",
  "title": "显示名",
  "queue_name": "队列里显示的名字",
  "entry": "arrival",
  "requires_stats": false,
  "fee": 60,
  "speakers": {
    "孙": {"name": "史密斯", "name_if": [{"if": "named", "name": "孙悟空"}]}
  },
  "potion": {
    "score": {"wisdom": -1, "emotion": 1, "will": 1},
    "score_name": "火气",
    "node": "potion.react"
  },
  "state": {"flags": {"named": {"type": "bool", "default": false}}},
  "nodes": [],
  "canon": [],
  "outcomes": {}
}
```

节点必须且只能有一个出口：

- `next`：继续。
- `choices`：玩家选择；至少有一条不带 `if` 的选项，避免卡死。
- `branch`：自动条件跳转；没有兜底时用 `next`。
- `outcome`：结案。

`steps` 是 `{speaker?, text, if?}`。`text` 是完整 key，例如 `wukong.arrival.2`。正文里可以用行内条件，见第 4 节。

`speakers` 的 `name` 是默认显示名；`name_if` 按顺序取第一条命中的 `name` 覆盖。真名揭露前用假名，叫破后把 `named` 置真，说话人自动切成真名。构建期会校验 `name_if` 的条件。

`choices` 是 `{id, kind?, text, if?, locked_if?, locked_text?, set?, next}`。`if` 为假时隐藏；`locked_if` 为真时显示但禁用。`kind` 取 `accept` / `refuse` 时，面板把它从普通对话选项里拆出来，放到面板底部，分别用绿色、红色按钮显示；不写 `kind` 的选项留在上方列表。

`branch` 是 `{if?, set?, next}`；按顺序取第一条命中的。

`potion.score` 是药性系数，公式为：

```text
得分 = 智慧 × wisdom + 情感 × emotion + 意志 × will
```

`potion.score_name` 是面板上显示的名字，例如“火气”“迷茫”；不写时显示“药性”。不喂药时用 `state.flags["dose.score"]` 的默认值。

`outcomes` 是：

```json
{
  "admitted": {
    "result": "release",
    "payout": 60,
    "ledger": {
      "who": "史密斯",
      "who_if": [{"if": "named", "who": "孙悟空"}],
      "result": "已入境",
      "note": "wukong.ledger.admitted.1"
    },
    "effects": ["world.hades_rampage = true"],
    "aftermath": ["wukong.end.admitted.1"]
  }
}
```

`aftermath` 是这个结局的“后来……”文字 key。接待窗口只显示选择结果和送客；这些 key 会存进当天收工后的“今日余波”报告，不提前在窗口里播。

`result` 取 `release`、`reject`、`stay`、`leave`。`ledger.note` 是文本 key；`ledger.who_if` 可选，按顺序取第一条命中的 `who` 覆盖默认值，用来在叫破身份后改账本上的名字。`effects` 只能是赋值或 `+=/-=`，不能调用游戏函数。

`callout` 是可选的真名输入，挂在案例顶层：

```json
"callout": {
  "answer": "SUNWUKONG",
  "prompt": "wukong.callout.prompt.1",
  "button": "wukong.callout.button.1",
  "success": "identify",
  "failure": "callout.fail",
  "time_limit": 20.0,
  "case_sensitive": false,
  "once": false
}
```

面板在选项节点显示“叫破”按钮；点击后进入打字模式，A-Z 顺序输入，输错重置，倒计时结束进 `failure` 节点。`success` 节点通常负责 `named = true`，并返回原来的选项节点。`answers` 可以给多个可接受答案，但第一个用于泡泡显示；当前演出只接受 A-Z，且不提示目标字母：未输入的字母都是圆点，只有玩家已经输入正确的字母会显示。

## 4. 正文 key 和行内条件

编译器按节名和行号生成 key：

```md
## arrival
（旁白）
孙：台词

## choice.photo
对照冥籍照片
```

- `arrival` 的行 → `<case>.arrival.1`、`.2`……
- `choice.photo` → `<case>.choice.photo`（必须只有一行）
- `choice` 以外的节可以多行。

`speakers` 里声明的简称或全名会被识别成说话人；不认识的冒号前缀按旁白处理。

正文支持行内条件：

```md
他{{if named}}竟是史诗中的英雄俄耳普斯转世，{{/if}}伪装成亡灵。
{{if world.hades_rampage}}冥王正在发脾气。{{else}}冥王睡得很好。{{/if}}
```

- 条件和分支图里用的是同一套表达式，例如 `named`、`!named`、`world.hades_rampage`。
- 支持 `{{else}}` 和嵌套；构建期会检查标签是否配对、条件里的 flag 是否声明。
- 运行时按当前案例/世界状态渲染，渲染结果里不会留下 `{{`。
- 目前只支持 `{{if ...}}`，不是通用模板语言；不要在正文里写其他花括号语法。

## 5. 编译

```powershell
& game\.tools\godot\Godot_v4.7.2-stable_win64_console.exe --headless --path game --script res://tools/story_build.gd
```

构建会检查：

- 未声明的 flag、非法条件、非法效果。
- 节点出口数量、未知节点、未知 outcome。
- 选项节点没有无条件选项。
- 缺失文本、未使用的正文、缺失 ledger note。
- 从 entry 走不到的节点。
- schedule 的日期/槽位/案例是否存在。
- 结局条件引用了不存在的案例。
- callout 的 answer/prompt/button/success/failure/time_limit。
- `potion.score_name` 类型。
- 正文行内条件的标签配对和条件语法。
- 演出 cue 的正文 key、类型、时长/延迟上限、道具 id、颜色格式和 `if` flag。

失败时退出码非 0，并写 `narrative/derived/story_build_report.md`。

### 5.1 演出 cue

动作演出写在 `narrative/derived/cues/<case>.cues.json`，按正文 key 挂载；正文本身不改：

```json
{
  "wukong.inspect.tail.2": [
    {"type": "prop", "id": "tail", "action": "hide", "delay": 0.4},
    {"type": "shake", "strength": 3, "duration": 0.3},
    {"type": "wait", "duration": 0.5}
  ]
}
```

- 可用类型：`shake`、`flash`、`fade`、`zoom`、`prop`、`sprite`、`wait`，以及预留的 `sound`。
- 道具 id：`lyre`、`staff`、`tail`、`coins`、`bowl`、`gray_hand`、`peach`、`cloud`。
- 立绘 id：`wukong_disguise`、`wukong_monkey`、`wukong_turn`、`orpheus_front`、`orpheus_turn`。
- `wait: true` 或 `type:"wait"` 会锁住正文推进；空格只跳过本组 cue，再按一次才推进。
- 参数上限：单 cue `duration` ≤ 3 秒，`delay` ≤ 8 秒。
- 构建会把 cue 合进 `game/data/story/cases/*.json` 的 step，运行时不读原始 cue 文件。
- 完整设计见 `docs/剧情演出与特效方案.md`。

### 5.2 演出素材

- 正式道具：`game/assets/art/story/props/`；正式立绘：`game/assets/art/story/sprites/`。
- 生成源图：`game/art/source/story/`（本地素材，Git 忽略）。
- 处理脚本：`game/tools/prepare_generated_asset.py`；素材清单：`game/tools/story_assets.json`。
- 重新生成全部正式图：

```powershell
& "game/.tools/perfect-pixel/venv/Scripts/python.exe" game/tools/prepare_generated_asset.py --config game/tools/story_assets.json
```

每张正式图旁的 `.json` 记录源图哈希、像素网格、目标尺寸和水印处理；`game/assets/SOURCES.md` 是素材来源总表。

## 6. 模拟

```powershell
& game\.tools\godot\Godot_v4.7.2-stable_win64_console.exe --headless --path game --script res://tools/story_sim.gd
```

模拟器对每个案例做：

- `world.hades_rampage` 为 false 和 true 各跑一遍，确保跨案例结局可达。
- 药按正/负/零各抽样一次，叫破按成功/失败各抽样一次。
- 枚举每个选择节点里可见的选项，直到结案。
- 检查每个声明的 outcome 至少有一条路径能到；缺了退出码非 0。

输出：

- `narrative/derived/simulation_report.md`：每个案例一节，包含路径数、演出覆盖、叫破/迷茫/大闹计数、结局分布和选项覆盖。
- `narrative/derived/combinations.csv`：列为 `case,world_rampage,path,outcome,named,confused,rage,dose_score`。

抽样只用于验证可达性，不是完整组合数；分支图本身的组合由运行时和测试保证。

## 8. 当前案例

- `wukong`：第 5 天、slot 4；11 个 step、25 条 cue。
  - 队列名“史密斯”，不剧透孙悟空；叫破前说话人也显示“史密斯”。
  - 四个调查点、输入真名 `SUNWUKONG` 叫破；叫破后说话人变成“孙悟空”。
  - 调查过的选项不会消失，会置灰并标“（已调查）”。
  - 接受/拒绝是底部独立的绿色/红色按钮。
  - 选择接受/拒绝后，窗口立即结案，只保留“结束招待”送客；结局后果在当天收工后的“今日余波”报告里看。
  - 药性火气 = 情感 + 意志 − 智慧；不喂默认 1。
  - 火气为正：接受/拒绝都会大闹，文本不同。
  - 火气为非正：他会在做决定前变成猴子飞走，结局 `calm`，当夜无事。
  - 三个结局：`admitted`、`refused`、`calm`。
- `orpheus`：第 5 天、slot 5；7 个 step、19 条 cue。
  - 队列名“亚历克斯”，不剧透身份；叫破前说话人也显示“亚历克斯”。
  - A 查看冥籍：他弹琴，圣地亚哥被迷惑，说“身份没问题”；只能看一次。
  - B 欧律狄刻？：问出妻子住在哈迪斯神庙，最后停在“她在冥界犯了什么罪”。
  - C 查看里拉琴：他不敢转身，露出“回头”的恐惧。
  - 输入真名 `ORPHEUS` 叫破；叫破后说话人变成“俄耳普斯”，账本和结局正文也会写真名。
  - 调查过的选项不会消失，会置灰并标“（已调查）”。
  - 接受/拒绝是底部独立的绿色/红色按钮。
  - 选择接受/拒绝后，窗口立即结案，只保留“结束招待”送客；结局后果在当天收工后的“今日余波”报告里看。
  - 药性迷茫 = 情感 − 意志 − 智慧；不喂默认 1。
  - 迷茫为正：接受后仍会在冥河回头，妻子被抓走。
  - 迷茫为非正：他能忍住不回头；若 `world.hades_rampage` 为真，猴子会打碎灰手，结局 `accepted.reunion`；否则妻子仍被抓走。
  - 四个结局：`accepted.confused`、`accepted.clear`、`accepted.reunion`、`refused`。
- 跨案例：`world.hades_rampage` 由孙悟空结案写入；俄耳普斯的 `accepted.reunion` 读它。

## 9. 实际试玩

### 9.1 最快：剧情测试场

双击 `启动/剧情测试.cmd`，或在仓库根目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\game\tools\Run-StoryLab.ps1
```

测试场会：

- 直接开始第 5 天，进入接待页。
- 自动处理掉四位普通来客，只留下“史密斯”和“亚历克斯”。
- 关闭存档，退出或回封面不会污染正常进度。
- 在左侧药剂列表放入三瓶测试药：
  - **暖心药**：情感 +4。
  - **极识药**：智慧 +10、意志 −4。
  - **零值药**：智慧 +1、意志 −1（仅测试场，用来打 0 分边界）。

操作还是正常接待：`A/D` 选来客，空格推进剧情，鼠标点“叫破”后输入字母，`W/S` 选药，`F` 喂药，`Shift` 结束接待。

### 9.2 孙悟空

1. 选“史密斯”，按空格看完开场，进入选项。
2. 可以查四个破绽，也可以直接点“叫破（输入真名）”，输入 `SUNWUKONG`。
3. 喂药看分支：

| 药剂 | 火气 | 结果 |
| --- | ---: | --- |
| 不喂 | 1 | 接受/拒绝都会大闹 |
| 暖心药 | +4 | 接受/拒绝都会大闹 |
| 极识药 | −14 | 他变成猴子飞走，结局 `calm` |
| 零值药 | 0 | 非正，他飞走，结局 `calm` |

4. 点底部绿色“接受入境”或红色“拒绝入境”，按 `Shift` 结束接待。

### 9.3 俄耳普斯

1. 选“亚历克斯”。
2. 可以点 A 查看冥籍、B 欧律狄刻？、C 查看里拉琴；A 只看一次，B/C 各留一条线索。
3. 点“叫破（输入真名）”，输入 `ORPHEUS`。
4. 喂药看迷茫值：

| 药剂 | 迷茫 | 状态 |
| --- | ---: | --- |
| 不喂 | 1 | 迷茫为正 |
| 暖心药 | +4 | 迷茫为正 |
| 极识药 | −6 | 非正，清醒 |
| 零值药 | 0 | 非正，清醒 |

5. 点底部绿色“接受入境”或红色“拒绝入境”。接受时：

| 悟空当夜 | 迷茫 | 结局 |
| --- | --- | --- |
| 任意 | 正 | `accepted.confused`：他回头，妻子被抓走 |
| 未大闹 | 非正 | `accepted.clear`：他忍住回头，妻子仍被抓走 |
| 已大闹 | 非正 | `accepted.reunion`：猴子打碎灰手，夫妻脱身 |
| — | — | `refused`：拒绝入境，他再次投河 |

**要测 `accepted.reunion`，先处理孙悟空并让他大闹，再处理俄耳普斯。** 如果先结俄耳普斯，`world.hades_rampage` 还没写入，他只会走 `accepted.clear`；之后再让悟空大闹也不会补回这个结局。

6. 按 `Shift` 结束接待，看羊皮纸里的账本和整局结局。

### 9.4 正常流程

双击 `启动/运行游戏.cmd`，从第 1 天玩到第 5 天。第 5 天最后两位就是剧情来客；前四位普通来客仍然按属性门槛接待。正常流程会走存档，适合验证读档和整局结局。

### 9.5 检查点

- 队列里只显示“史密斯”“亚历克斯”，不提前剧透。
- 叫破后账本名字变成“孙悟空”“俄耳普斯”；没叫破保持假名。
- 喂药后左侧提示分别显示“火气”和“迷茫”，不是写死的“火气”。
- 俄耳普斯的结局正文里，叫破后才出现“竟是史诗中的英雄俄耳普斯转世”；没叫破时整段隐藏。
- 叫破时泡泡里不会提前显示任何目标字母；只有输入正确的字母会亮出来。
- 调查尾巴、金箍棒、里拉琴时，能看到对应道具；弹琴、收起尾巴时有震动/闪光。
- 悟空叫破后从白人伪装切成猴子本相；俄耳甫斯查看里拉琴时会转身，随后切回正面。

- 演出期间文字面板保持可读，不被震动或闪色干扰。

## 10. 已知边界

- 剧情面板使用 5 张 64×96 静态立绘；`speakers[].art` 字段仍未使用。
- 结局后果延迟到当天收工报告；报告关闭后才进入下一天或整局结局。
- 道具和立绘都是 AI 生成的正式像素图，源图/处理记录见 `game/assets/SOURCES.md`。
- `sprite` 是静态换图，没有帧动画；`sound` 的素材清单为空，写了会构建失败。
- 一个特殊来客只能请一味药；要改成多味需要把药性改成累计值并补测试。
- 打字叫破目前只接受 A-Z；中文名字需要接输入法或 LineEdit。
- 模拟器按案例枚举，药和叫破各抽样一次；它不是完整笛卡尔积，也不模拟玩家实际排队顺序。
- 俄耳甫斯的 `accepted.reunion` 依赖结案时的 `world.hades_rampage`；先结俄耳甫斯就拿不到。要改成为“当夜结算”需要把案例结局延迟到整局结束。
