# 剧情系统使用说明

> 系统设计见 `docs/剧情系统设计.md`。这篇只讲怎么加案例、怎么编译、怎么跑测试。

## 1. 目录

```text
narrative/
  seeds/                 人写：故事种子
  derived/               AI 生成：分支图、调度、世界状态、结局
    wukong.graph.json
    schedule.json
    world.json
    endings.json
    story_build_report.md
    simulation_report.md
    combinations.csv
  prose/                 人写：按节点分节的正文
    wukong.md
    endings.md

game/scripts/story/      运行时：表达式、状态、文本、案例、单案例推进
game/scripts/demo/story_panel.gd   接待窗口里的剧情面板
game/tools/story_build.gd          编译与校验
game/tools/story_sim.gd            路径枚举与报告
game/data/story/                   编译产物，游戏只读这里
```

`game/data/story/` 是生成目录，不手改；改 `narrative/` 后重新编译。

## 2. 写一个案例

1. **种子**：`narrative/seeds/<id>.md`。写清谁、想要什么、藏了什么、玩家能做什么、必须发生、绝不能发生。
2. **分支图**：`narrative/derived/<id>.graph.json`。结构见第 3 节。
3. **正文**：`narrative/prose/<id>.md`。按节点分节，台词用 `说话人：内容`，旁白直接写。不用写 key。
4. **排期**：在 `narrative/derived/schedule.json` 的 `slots` 里加 `{day, slot, case}`；`slot` 从 0 开始。
5. **世界状态**：需要跨案例的 flag 写进 `narrative/derived/world.json`。
6. **整局结局**：需要新结局写进 `narrative/derived/endings.json`，正文写在 `narrative/prose/endings.md`。
7. 跑编译和测试。

## 3. 分支图约定

```json
{
  "id": "case_id",
  "title": "显示名",
  "queue_name": "队列里显示的名字",
  "entry": "arrival",
  "requires_stats": false,
  "fee": 60,
  "speakers": {"孙": {"name": "孙悟空"}},
  "potion": {"score": {"wisdom": -1, "emotion": 1, "will": 1}, "node": "potion.react"},
  "state": {"flags": {"named": {"type": "bool", "default": false}}},
  "nodes": [],
  "canon": [],
  "outcomes": {}
}
```

节点必须且只能有一个出口：

- `next`：继续。
- `choices`：玩家选择；至少有一条不带 `if` 的选项，避免卡死。
- `branch`：自动条件跳转；没有兜底时用 `next`。
- `outcome`：结案。

`steps` 是 `{speaker?, text, if?}`。`text` 是完整 key，例如 `wukong.arrival.2`。

`choices` 是 `{id, text, if?, locked_if?, locked_text?, set?, next}`。`if` 为假时隐藏；`locked_if` 为真时显示但禁用。

`branch` 是 `{if?, set?, next}`；按顺序取第一条命中的。

`outcomes` 是：

```json
{
  "admitted": {
    "result": "release",
    "payout": 60,
    "ledger": {"who": "史密斯", "result": "已入境", "note": "wukong.ledger.admitted.1"},
    "effects": ["world.hades_rampage = true"]
  }
}
```

`result` 取 `release`、`reject`、`stay`。`ledger.note` 是文本 key。`effects` 只能是赋值或 `+=/-=`，不能调用游戏函数。

## 4. 正文 key

编译器按节名和行号生成 key：

```md
## arrival
（旁白）
孙：台词

## choice.photo
对照冥籍照片
```

- `arrival` 的行 → `<case>.arrival.1`、`.2`……
- `choice.photo` → `<case>.choice.photo`（必须只有一行）
- `choice` 以外的节可以多行。

`speakers` 里声明的简称或全名会被识别成说话人；不认识的冒号前缀按旁白处理。

## 5. 编译

```powershell
& game\.tools\godot\Godot_v4.7.2-stable_win64_console.exe --headless --path game --script res://tools/story_build.gd
```

构建会检查：

- 未声明的 flag、非法条件、非法效果。
- 节点出口数量、未知节点、未知 outcome。
- 选项节点没有无条件选项。
- 缺失文本、未使用的正文、缺失 ledger note。
- 从 entry 走不到的节点。
- schedule 的日期/槽位/案例是否存在。
- 结局条件引用了不存在的案例。

失败时退出码非 0，并写 `narrative/derived/story_build_report.md`。

## 6. 模拟

```powershell
& game\.tools\godot\Godot_v4.7.2-stable_win64_console.exe --headless --path game --script res://tools/story_sim.gd
```

输出：

- `narrative/derived/simulation_report.md`：路径数、结局分布、选项覆盖。
- `narrative/derived/combinations.csv`：每条路径的结局、是否叫破、是否大闹、药性值。

模拟器会检查每个声明的 outcome 至少有一条路径能到；缺了会退出码非 0。

## 8. 当前案例

- `wukong`：第 5 天、第 5 位（slot 5）。
- 队列名“史密斯”，不剧透孙悟空。
- 四个调查点、叫破、接受/拒绝。
- 药性火气 = 情感 + 意志 − 智慧；非负大闹，为负无事；不喂默认大闹。
- 四个结局：`admitted.rage`、`admitted.calm`、`refused.rage`、`refused.calm`。
- 账本记“史密斯/孙悟空”，整局结局会读 `case.wukong.named`。

## 9. 已知边界

- 剧情面板目前是文字 + 选项，没有专门立绘或演出；`speakers[].art` 字段保留但未接。
- 一个特殊来客只能请一味药；要改成多味需要把药性改成累计值并补测试。
- 模拟器按案例枚举，还没有做多案例笛卡尔积；跨案例 flag 和结局条件已经支持。
- 整局结局显示在接待窗口的羊皮纸里，没有单独的结局界面。
- `narrative/` 是内容源，`game/data/story/` 是编译产物；不要反过来改。
