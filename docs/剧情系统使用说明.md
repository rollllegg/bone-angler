# 剧情系统使用说明

> 系统设计见 `docs/剧情系统设计.md`。这篇只讲怎么加案例、怎么编译、怎么跑测试、怎么实际试玩。
>
> 动作旁白的演出与特效见 `docs/剧情演出与特效方案.md`（P1 屏幕特效、P2 道具、P3 特殊立绘已实现，P4 音效待素材）。

## 1. 目录

```text
narrative/
  seeds/                 人写：故事种子
    wukong.md
    orpheus.md
  derived/               AI 生成：分支图、调度、世界状态、结局
    wukong.graph.json
    orpheus.graph.json
    schedule.json
    world.json
    endings.json
    story_build_report.md
    simulation_report.md
    combinations.csv
  prose/                 人写：按节点分节的正文
    wukong.md
    orpheus.md
    endings.md

game/scripts/story/                   运行时：表达式、状态、文本、案例、单案例推进
game/scripts/demo/story_panel.gd      真名输入的打字挑战
game/scripts/demo/story_hotspot_layer.gd 立绘热点、悬停提示与已调查状态
game/tools/story_build.gd             编译与校验
game/tools/story_sim.gd               路径枚举与报告
game/tools/Run-StoryLab.ps1           剧情测试场启动脚本
game/data/story/                      编译产物，游戏只读这里
```

`game/data/story/` 是生成目录，不手改；改 `narrative/` 后重新编译。

## 2. 写一个案例

1. **种子**：`narrative/seeds/<id>.md`。写清谁、想要什么、藏了什么、玩家能做什么、必须发生、绝不能发生。
2. **分支图**：`narrative/derived/<id>.graph.json`。结构见第 3 节。
3. **正文**：`narrative/prose/<id>.md`。按节点分节，台词用 `说话人：内容`，必要旁白直接写；括号里的动作描写不写进文本框，改在 cue 里做动画/特效。不用写 key。
4. **排期**：在 `narrative/derived/schedule.json` 的 `slots` 里加 `{day, slot, case}`；`slot` 从 0 开始。
5. **世界状态**：需要跨案例的 flag 写进 `narrative/derived/world.json`。
6. **整局结局**：需要新结局写进 `narrative/derived/endings.json`，正文写在 `narrative/prose/endings.md`。
7. 跑编译和测试。

## 3. 分支图约定

```json
{
  "id": "case_id",
  "title": "显示名",
  "queue_name": "队列里显示的名字",
  "entry": "arrival",
  "requires_stats": false,
  "fee": 60,
  "speakers": {
    "孙": {"name": "史密斯", "name_if": [{"if": "named", "name": "孙悟空"}]}
  },
  "potion": {
    "score": {"wisdom": -1, "emotion": 1, "will": 1},
    "score_name": "火气",
    "node": "potion.react"
  },
  "state": {"flags": {"named": {"type": "bool", "default": false}}},
  "nodes": [],
  "canon": [],
  "outcomes": {}
}
```

节点必须且只能有一个出口：

- `next`：继续。
- `choices`：玩家选择；至少有一条不带 `if` 的选项，避免卡死。
- `branch`：自动条件跳转；没有兜底时用 `next`。
- `outcome`：结案。

`steps` 是 `{speaker?, text, if?}`。`text` 是完整 key，例如 `wukong.arrival.2`。正文里可以用行内条件，见第 4 节。

`speakers` 的 `name` 是默认显示名；`name_if` 按顺序取第一条命中的 `name` 覆盖。真名揭露前用假名，叫破后把 `named` 置真，说话人自动切成真名。构建期会校验 `name_if` 的条件。

`choices` 是 `{id, kind?, text, hotspot?, if?, locked_if?, locked_text?, set?, next}`。`if` 为假时隐藏；`locked_if` 为真时显示但禁用。不写 `kind` 的调查选项必须带 `hotspot`，在接待窗口里画在立绘上；点热点等于选这条。`kind` 取 `accept` / `refuse` 时不走热点，仍由右下角按钮处理。

热点坐标是 48×64 立绘像素，一个选项可以给多个矩形：

```json
{
  "id": "tail",
  "text": "wukong.choice.tail",
  "locked_if": "clue.tail != 0",
  "locked_text": "wukong.choice.tail.locked",
  "set": ["clue.tail = 1"],
  "next": "inspect.tail",
  "hotspot": {
    "rects": [[26, 37, 10, 8]],
    "variants": {"wukong_monkey": [[22, 48, 8, 8]]}
  }
}
```

`rects` 是默认形态的热点；换立绘后位置变化时，用 `variants` 按立绘 id 覆盖，例如悟空的尾巴在伪装和本相下位置不同。没有列出的立绘沿用 `rects`。

热点由 `game/scripts/demo/story_hotspot_layer.gd` 映射到屏幕：鼠标悬停显示动作名，已调查的选项画灰并显示「已调查」，点击仍调用 `runtime.choose(id)`。`pixel_shop.get_story_portrait_rect()` 负责把店铺 405×243 视口里的立绘位置换算到 1620×972 舞台。

`branch` 是 `{if?, set?, next}`；按顺序取第一条命中的。

`judgment` 是可选的数量判定，挂在没有 `steps` 或读完 `steps` 后的节点上：

```json
{
  "id": "judgment",
  "judgment": {"min": 0, "prompt": "anubis.judgment.prompt.1"},
  "branch": [
    {"if": "offering <= 0", "next": "end.zero"},
    {"if": "offering >= offering_max", "next": "end.all"},
    {"next": "end.other"}
  ]
}
```

运行时暂停正文，等待界面提交一个整数；`start_judgment(max)` 把上限写进 `offering_max`，`resolve_judgment(value)` 把结果写进 `offering`，然后按 `branch` 继续。`min` 默认 0。判定节点只能有一个出口，且不能和 `choices` 同节点。

`potion.score` 是药性系数，公式为：

```text
得分 = 智慧 × wisdom + 情感 × emotion + 意志 × will
```

`potion.score_name` 是面板上显示的名字，例如“火气”“迷茫”；不写时显示“药性”。不喂药时用 `state.flags["dose.score"]` 的默认值。

`outcomes` 是：

```json
{
  "admitted": {
    "result": "release",
    "payout": 60,
    "ledger": {
      "who": "史密斯",
      "who_if": [{"if": "named", "who": "孙悟空"}],
      "result": "已入境",
      "note": "wukong.ledger.admitted.1"
    },
    "effects": ["world.hades_rampage = true"],
    "aftermath": ["wukong.end.admitted.1"]
  }
}
```

`aftermath` 是这个结局的“后来……”文字 key。接待窗口只显示选择结果和送客；这些 key 会存进当天收工后的“今日余波”报告，不提前在窗口里播。俄耳普斯殉情是例外：第 3 天琴手回访后才进报告。

`result` 取 `release`、`reject`、`stay`、`leave`、`judged`。`judged` 用于最后的天平判定，不付服务费，但计入已处理人数。`report` 为 `false` 时只写账本、不生成当天“今日余波”条目；`tally` 为 `false` 时不增加放行/拒绝计数。`ledger.note` 是文本 key；`ledger.who_if` 可选，按顺序取第一条命中的 `who` 覆盖默认值，用来在叫破身份后改账本上的名字。`effects` 只能是赋值或 `+=/-=`，不能调用游戏函数。

`callout` 是可选的真名输入，挂在案例顶层：

```json
"callout": {
  "answer": "SUNWUKONG",
  "prompt": "wukong.callout.prompt.1",
  "button": "wukong.callout.button.1",
  "success": "identify",
  "failure": "callout.fail",
  "time_limit": 20.0,
  "case_sensitive": false,
  "once": false
}
```

接待窗口在右下角显示「真名解放」。点击后按顺序输入 A–Z 字母。输错会重置进度，倒计时结束进入 `failure` 节点。`success` 节点通常负责 `named = true`，并返回原来的选项节点。`answers` 可以给多个可接受答案，但第一个用于泡泡显示；当前演出只接受 A-Z，且不提示目标字母：未输入的字母都是圆点，只有玩家已经输入正确的字母会显示。

## 4. 正文 key 和行内条件

编译器按节名和行号生成 key：

```md
## arrival
（旁白）
孙：台词

## choice.photo
看他的脸
```

- `arrival` 的行 → `<case>.arrival.1`、`.2`……
- `choice.photo` → `<case>.choice.photo`（必须只有一行）
- `choice` 以外的节可以多行。

`speakers` 里声明的简称或全名会被识别成说话人；不认识的冒号前缀按旁白处理。

正文支持行内条件：

```md
他{{if named}}竟是史诗中的英雄俄耳普斯转世，{{/if}}伪装成亡灵。
{{if world.hades_rampage}}冥王正在发脾气。{{else}}冥王睡得很好。{{/if}}
```

- 条件和分支图里用的是同一套表达式，例如 `named`、`!named`、`world.hades_rampage`。
- 支持 `{{else}}` 和嵌套；构建期会检查标签是否配对、条件里的 flag 是否声明。
- 运行时按当前案例/世界状态渲染，渲染结果里不会留下 `{{`。
- 目前只支持 `{{if ...}}`，不是通用模板语言；不要在正文里写其他花括号语法。

## 5. 编译

```powershell
& game\.tools\godot\Godot_v4.7.2-stable_win64_console.exe --headless --path game --script res://tools/story_build.gd
```

构建会检查：

- 未声明的 flag、非法条件、非法效果。
- 节点出口数量、未知节点、未知 outcome。
- 选项节点没有无条件选项。
- 缺失文本、未使用的正文、缺失 ledger note。
- 从 entry 走不到的节点。
- schedule 的日期/槽位/案例是否存在。
- 结局条件引用了不存在的案例。
- callout 的 answer/prompt/button/success/failure/time_limit。
- `potion.score_name` 类型。
- 正文行内条件的标签配对和条件语法。
- 演出 cue 的正文 key、类型、时长/延迟上限、道具 id、颜色格式和 `if` flag。
- 每个非 `accept` / `refuse` 选项都有热点，默认矩形和 `variants` 都落在 48×64 内。
- `judgment` 节点有数值 `min`、可读的 prompt、且只有一个分支/`next` 出口；不能和 `choices` 同节点。

失败时退出码非 0，并写 `narrative/derived/story_build_report.md`。

### 5.1 演出 cue

动作演出写在 `narrative/derived/cues/<case>.cues.json`，按正文 key 挂载；正文本身不改：

```json
{
  "wukong.inspect.tail.1": [
    {"type": "prop", "id": "tail", "action": "show"},
    {"type": "shake", "strength": 3, "duration": 0.3},
    {"type": "prop", "id": "tail", "action": "hide", "delay": 0.8},
    {"type": "wait", "duration": 0.5}
  ]
}
```

- 可用类型：`shake`、`flash`、`fade`、`zoom`、`prop`、`sprite`、`wait`，以及预留的 `sound`。
- 道具 id：`lyre`、`staff`、`tail`、`coins`、`bowl`、`gray_hand`、`peach`、`cloud`、`scale`。
- 立绘 id：`wukong_disguise`、`wukong_disguise_turn`、`wukong_monkey`、`wukong_turn`、`orpheus_front`、`orpheus_revealed`、`orpheus_turn`、`anubis`、`anubis_turn`。
- `wait: true` 或 `type:"wait"` 会锁住正文推进；空格只跳过本组 cue，再按一次才推进。
- 参数上限：单 cue `duration` ≤ 3 秒，`delay` ≤ 8 秒。
- 构建会把 cue 合进 `game/data/story/cases/*.json` 的 step，运行时不读原始 cue 文件。
- 完整设计见 `docs/剧情演出与特效方案.md`。

### 5.2 演出素材

- 正式道具：`game/assets/art/story/props/`；正式立绘：`game/assets/art/story/sprites/`。
- 生成源图：`game/art/source/story/`（本地素材，Git 忽略）。
- 处理脚本：`game/tools/prepare_generated_asset.py`；素材清单：`game/tools/story_assets.json`。
- 重新生成全部正式图：

```powershell
& "game/.tools/perfect-pixel/venv/Scripts/python.exe" game/tools/prepare_generated_asset.py --config game/tools/story_assets.json
```

每张正式图旁的 `.json` 记录源图哈希、像素网格、目标尺寸和水印处理；`game/assets/SOURCES.md` 是素材来源总表。

## 6. 模拟

```powershell
& game\.tools\godot\Godot_v4.7.2-stable_win64_console.exe --headless --path game --script res://tools/story_sim.gd
```

模拟器对每个案例做：

- `world.hades_rampage` 为 false 和 true 各跑一遍，确保跨案例结局可达。
- 药按正/负/零各抽样一次，叫破按成功/失败各抽样一次。
- 枚举每个选择节点里可见的选项，直到结案。
- 检查每个声明的 outcome 至少有一条路径能到；缺了退出码非 0。

输出：

- `narrative/derived/simulation_report.md`：每个案例一节，包含路径数、演出覆盖、叫破/迷茫/大闹计数、结局分布和选项覆盖。
- `narrative/derived/combinations.csv`：列为 `case,world_rampage,path,outcome,named,confused,rage,dose_score`。

抽样只用于验证可达性，不是完整组合数；分支图本身的组合由运行时和测试保证。

## 9. 实际试玩

正常运行 `启动/运行游戏.cmd` 即可按排期接待三位特殊来客。双击 `启动/剧情测试.cmd` 进入剧情测试场：从第 1 天开始，普通来客已被清理，只保留剧情相关来客，预备三瓶药并关闭存档。按 `N` 直接进入下一天：第 1 天是悟空和伪装观察者，第 2 天是俄耳普斯，第 3 天是琴手回访（需先让俄耳普斯殉情），第 4 天没有剧情客，第 5 天是阿努比斯。重开测试场即可从第 1 天重来。

测试场里按 `N` 直接进入下一天；其余操作与正常游戏一致。按 A / D 选来客，W / S 选药，空格给药，Shift 放行。读完开场后点立绘上的可疑部位调查；调查对话用空格或点击对话框继续。点「真名解放」后输入字母，Esc 可取消。悟空和俄耳普斯解放真名后可以点「拒绝入境」结案；阿努比斯是线性听证，叫破后直接继续到天平。当天清空接待队列后，在「今日余波」查看结果（阿努比斯除外）。

### 孙悟空

火气等于情感加意志减智慧，默认是 1。火气为正时，放行或拒绝都会引起大闹。火气为零或负时，药会触发自行离开的结局，可按 Shift 送客。

### 俄耳普斯

迷茫等于情感减意志和智慧，默认是 1。放行时，迷茫为正会触发回头的结局。迷茫为零或负时，他能忍住回头。如果孙悟空已经大闹冥府，夫妻可脱身。

如果俄耳普斯殉情（回头、忍住但被灰手抓走、或拒绝入境），第 3 天最后一位会出现特殊立绘的「殉情的琴手」，按普通来客流程接待；他离开后，俄耳普斯的“后来……”才在当天收工报告里出现。夫妻脱身的分支仍在第 2 天收工报告里直接播放。

### 阿努比斯

第 1 天最后一位是普通立绘、全满属性、免检、喝药不改变数值的观察者。第 5 天最后一位是真身：听完他对悟空和俄耳普斯的评价后，可以把 0 到当前渡魂币总数的整数放上天平。0、全部、其他分别进入三段结局；叫破 `ANUBIS` 才会看到方括号里的卢苇原邀请。称心结束后不再弹当天报告，直接进入结局卡：接待界面隐藏，只保留阿努比斯、天平、结局文字和返回标题提示。

## 10. 已知边界

- 剧情素材包含 9 张 48×64 静态立绘；`speakers[].art` 字段仍未使用。
- 俄耳普斯默认使用 `orpheus_front`（兜帽 + 里拉琴），叫破真名后切到 `orpheus_revealed`；孙悟空叫破后从 `wukong_disguise` 切到 `wukong_monkey`。
- 热点坐标按 48×64 立绘手写；改立绘后要同步调 `hotspot.rects`，构建期只校验边界，不校验是否压在角色像素上。
- 剧情后果通常显示在当天的收工报告；俄耳普斯殉情会推迟到第 3 天琴手回访，阿努比斯的称心则直接进入整局结局，不生成报告。
- 道具和立绘都是 AI 生成的正式像素图，源图/处理记录见 `game/assets/SOURCES.md`。
- `sprite` 是静态换图，没有帧动画；`sound` 的素材清单为空，写了会构建失败。
- 一个特殊来客只能请一味药；要改成多味需要把药性改成累计值并补测试。
- 打字叫破目前只接受 A-Z；中文名字需要接输入法或 LineEdit。
- 模拟器按案例枚举，药和叫破各抽样一次；它不是完整笛卡尔积，也不模拟玩家实际排队顺序。
- 俄耳普斯的 `accepted.reunion` 依赖结案时的 `world.hades_rampage`；正常排期先悟空后俄耳普斯。殉情分支的“后来……”由第 3 天琴手回访触发，存档会保留待播放的 `world.orpheus_echo`。
- 阿努比斯的判定上限取打开天平时的 `session.coins`；判定期间时间暂停。天平与阿努比斯立绘是占位美术，倾斜/回正由代码动画完成。
