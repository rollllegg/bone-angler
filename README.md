# Bone Angler · 骨灰级钓手

## 整体试玩 Demo

双击 `启动/运行游戏.cmd`，或运行已导出的 `game/build/windows/BoneFishing.exe`。封面选中「开始游戏」后，可以在冥河钓鱼、到炼药台处理鱼获、给灵魂端药，再手动放行。试玩共五天，每天 6 位来客，共 30 位。来客间隔为 20～25 秒。

| 界面 | 键盘操作 |
| --- | --- |
| 封面 | W / S 选择，空格确认，C 返回。「继续游戏」可选择存档 |
| 河岸（Q） | 空格抛竿，X 中断收竿。按箭头对应的 WASD 或方向键逆向拉鱼。点拉到边界点按，绷线持续按住，猛冲金环亮起时松开 |
| 钓组 | Shift 开始换件，时间照常流逝。W / S 选槽位，空格打开列表。鱼饵用 WASD 选择，其他部件用 W / S，空格确认。C 逐级返回 |
| 接待（E） | A / D 选等候的来客，W / S 选药剂并预览，空格喂药，Shift 放行 |
| 鱼篓与炼药（R） | WASD 在网格中选择，空格提炼鱼获或放入原液，Shift 切换提炼／复方，F 确认配制复方 |
| 市场（T） | W / S 选类别，空格进入，再用 W / S 选商品、空格解锁工艺、补充鱼饵或维修。A / D 调整鱼饵数量，夜市按 F 开始次日，C 返回上一级 |
| 暂停 | P / Esc 暂停，A / D 或 W / S 选择继续游戏、保存游戏、读取存档或返回封面，空格确认。C 返回上一级。切出游戏时默认自动暂停 |

游戏提供三个手动存档位。暂停后可直接存入空位，选择已有进度的位置时需确认覆盖。返回封面前可手动保存，封面的「继续游戏」也能读取存档。v1.4／v1.5 单一存档可在第一个存档位迁移读取，原文件保留。绷线进度随存档保存，读档后重新按住对应方向键即可继续。

当前经营规则为 2026-11-23 v1.5，与工作区《炼药放行与货币系统总整理》一致。开局 0 金币，赠灰鳞、冥河原液各 1 份，以及短杆、中号钩、平衡握柄与 10 个素指骨饵。第一位来客为（5，5，8），先制作通情药，再一剂放行取得 100 金币。素指骨饵可在市场免费重复领取，每次有效上钩仍消耗 1 个。

共 10 种常规鱼与 1 种巨刺鱼，11 种固定原液、66 种双原液复方；保留三组中和。静鳍鳅与三种降属性鱼饵已移除，细屑、匀魂、厚髓饵恢复为对应体型权重 ×3。智慧、情感、意志饵按专项固定鱼种名单提高权重。幽灯小型恢复普通身份，三档提炼为 1／2／3 份，不产浓缩的灵魂，强化不启用。

基础出现权重按隐式药效定位分配：浅水六种基础鱼各1/6；深水四种基础鱼各10%、四种进阶鱼各15%，进阶合计60%。这些为无定向饵、默认鱼群下普通鱼池的概率。鱼类事件100%；深水异刺饵另以20%进入巨刺分支，其余80%分配为基础合计32%、进阶合计48%。属性饵仍对指定鱼种权重×3，体型饵仍只改变大小。

每名灵魂最多服用 1 剂原液或复方，三项都在 7—9 才可放行，药效超出 0—10 时禁止使用，不截断数值。来客从当前可获取材料的一剂可解池生成，排除初始合规及任何单份基础原液能救赎的状态。每天 1—3 名灵魂显示公开精确目标，须有至少两个不同合格终点。普通放行 100 金币，精确命中 130 金币。

巨刺原液为（＋4，0，－1），极识药为（＋8，0，－2）。含巨刺的复方只要放行合规就触发完美救赎，报酬 130，不要求精确目标；与精确命中不叠加，两份巨刺也不翻倍。单独使用巨刺原液没有自动完美特权。

钓具永久解锁合计 400 金币，非巨刺鱼饵工艺合计 500，全部普通工艺完成后可再花 500 解锁异刺拟饵，次日生效；补充价格细屑／匀魂／属性饵 1，厚髓与异刺 2。平衡／耐久／速率握柄上限 12／15／10，共用累计磨损，切换不清除磨损；5 金币修复整套。沿用现有即时换装表现，握柄专项的拆装耗时尚未实现。

每天 6 位来客，全部放行或失败送离后进入当晚市场；按 F 或“开始次日”继续，先完成夜市采购再生成次日名单。失败用药不能补第二剂，可无报酬送离。新规则保留三个手动存档位，文件为 `user://bone_angler_v15_slot_1.json` 至 `slot_3.json`；第一个空槽可承接旧 `bone_angler_save_v15.json` 或 v1.4 的 `bone_angler_save_v14.json`。v1.4 迁移移除遗骨和遗骨饵，一次退回已付工艺费80及库存每份1金币，原文件保留；更早的强化／静鳍版本不混用。目标、配方身份、用药次数、夜市状态、解锁和共享磨损随存档保存。

确认操作会以本局独立记录原子保存。读取同一局的旧手动槽时沿用最新已确认状态，避免恢复已消耗的药剂、用药机会或重复结算。其他局的手动存档和原旧版文件保留。

来客达到三项 7—9 后，按 Shift 放行，灵魂会沿石路走入冥府大门。前一位离场时即可接待下一位。切换地点会保留抛竿、拉鱼与送客动画进度。

浮漂入水后等 3～8 秒上钩，通常为 5 秒。上钩前收竿会保留鱼饵和耐久。候鱼时切换地点，候鱼计时继续。在其他页面时有鱼上钩，屏幕左侧会弹出感叹号气泡，河岸按钮的 Q 也会变成红色感叹号。按 Q 或点击河岸按钮，在 3 秒内返回可开始拉鱼或真名捕获。超时后鱼会脱钩，上钩时消耗的鱼饵和耐久照常扣除。每次有效上钩都是鱼事件，链颌鱼的指骨副产物保留。暂停或离开河岸后，重新按住对应方向键即可继续绷线。

背景和动态鱼线按 405×243 像素网格绘制，界面独立叠加。河景、店铺、鱼竿、封面与灵魂帧均已通过 PerfectPixel，仓库包含 `game/assets/art/demo/` 下的运行素材与 `sources.json` 来源记录。详细制作记录 `game/assets/SOURCES.md` 和原始生成图 `game/art/source` 保留在本地，不影响克隆后运行 Demo。

新入口为 `game/scenes/demo/demo.tscn`。旧的组装、字母钓鱼和独立玩法练习仍保留在 `game/scenes/main.tscn`，可在编辑器中单独运行。

## 开发环境

- Windows 64 位。
- Godot **4.7.2 Standard**，使用 GDScript 和 Compatibility 兼容渲染模式。
- Godot **4.7.2** 导出模板，用于导出 Windows x64 和 Web 版本。
- Git，用于版本管理。
- Python **3.10**，用于本地预览 Web 版本。
- 可选：VS Code 和 Godot Tools **2.7.1** 扩展；也可以使用 Godot 内置脚本编辑器。

工具版本、下载地址和校验值统一记录在 `game/tools/toolchain.json`。

在仓库根目录运行：

## 像素图后处理

本项目以后新生成或重新生成的像素图，交付前统一经过 [PerfectPixel](https://github.com/theamusing/perfectPixel) 处理并检查。

- 将一张或多张图片拖到 `启动/像素图后处理.cmd` 上处理。
- 原图保留，结果另存为同目录下的 `原文件名.perfect.png`，并附带 `.perfect.json` 处理记录。已有结果不会被覆盖。
- 默认保留采样得到的透明通道，关闭自动补行、删行的正方形修正；仍需检查实际输出尺寸、细线和动画帧的一致性。
- 自动识别失败时，可指定 `--grid 宽 高` 重试；原图与处理稿保存在 `game/art/source`，确认后的正式素材放入 `game/assets/art`，并记录在 `game/assets/SOURCES.md`。

首次安装或在另一台电脑上准备工具：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\game\tools\Install-PerfectPixel.ps1
```

指定网格或输出位置：

```powershell
.\game\.tools\perfect-pixel\venv\Scripts\python.exe .\game\tools\perfect_pixel.py "原图.png" --grid 64 64 --output "处理稿.png"
```

源码与处理环境位于 `game/.tools/perfect-pixel/`，上游提交与源码压缩包校验值固定在 `game/tools/toolchain.json`；安装脚本复用已有兼容依赖，缺失的依赖仅安装到项目内的 Python 环境。

## 导出与本地预览

```powershell

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\game\tools\Build.ps1 -Target All

# 启动本地 Web 预览服务
python .\game\tools\serve_web.py
```

导出文件分别位于 `game/build/windows/` 和 `game/build/web/`；本地预览地址为 <http://127.0.0.1:8060>。

试玩界面使用缝合像素字体 12 px 简体比例版，Noto Sans SC 用于缺字回退和旧练习场景。两款字体的来源和 SIL Open Font License 1.1 许可位于 `game/assets/fonts/`。工具安装目录、Godot 缓存和导出文件不纳入版本管理。
